# Синхронизация справки с GitHub

Рабочая справка установлена на `https://forms.eduinterpain.ru/spravka`.
Этот документ описывает подготовленную версию и безопасные границы следующего шага.
Слияние в `main`, изменение рабочего каталога сервера и перезапуск сервиса отдельно
не разрешались и в рамках подготовки не выполняются.

## Что нужно сохранить

- Заголовок `ID паспорта | Кодовое обозначение | Название мероприятия | Город`.
- Сортировка только по кодовому обозначению, не по ID.
- Скалярный фильтр сделок `=UF_CRM_DEAL_1738519959225` отдельно по каждому паспорту:
  групповой IN-фильтр возвращал HTTP 500, скалярный запрос проверен пользователем.
- Полная пагинация, фильтрация по стадиям и защита от повторного подсчёта сделок.
- Локальный шрифт без внешних CDN.
- Исправления `event-register.html` и CSP в `server.js`, которые были на VPS до установки.

Действующий серверный `.env` не включается в коммиты или патчи.
В частности, пароль справки и URL вебхука не должны попадать в GitHub.

## Как не запустить Vercel

В подготовленной версии `vercel.json` содержит:

```json
{
  "git": {
    "deploymentEnabled": false
  }
}
```

Это фрагмент существующего файла, а не инструкция заменить весь файл.
Настройка отключает автоматические Git-развёртывания согласно
[документации Vercel](https://vercel.com/docs/project-configuration/git-configuration).
Она не отключает установленную GitHub App и не меняет старую версию `main`,
пока изменения туда не слиты.

У существующего PR ранее сработала интеграция Vercel.
При строгом требовании не запускать Vercel перед отправкой ветки нужно согласовать
и отключить Git-привязку именно существующего проекта `interpain-b24forms`
к этому репозиторию в Vercel.
Не удалять проект, аккаунт, другие интеграции, домены или существующие развёртывания.
Если реальная привязка или принадлежность проекта отличается от ожидаемой,
остановиться и уточнить её.

После подтверждённого отключения:

```bash
git push origin feature/events-spravka
```

Далее обновить описание PR, проверить его head SHA и отсутствие нового Vercel deployment.
PR оставить открытым. Auto-merge не включать.

## Безопасная проверка установленного кода

Подготовлен автономный `scripts/check-spravka-sync.cjs`.
Он сравнивает SHA-256 девяти известных файлов приложения с подготовленной версией.
Скрипт не читает `.env`, не делает сетевых запросов и не меняет файлы, Git или сервис.
Код завершения `0` означает совпадение всех девяти файлов, `1` означает расхождение
или отсутствие файла. Это не проверка всех файлов репозитория и не проверка секретов.

При запуске из репозитория:

```bash
node scripts/check-spravka-sync.cjs /opt/interpain_b24forms
```

Если отдельный файл скрипта перенесён на сервер в `/root`:

```bash
node /root/check-spravka-sync.cjs /opt/interpain_b24forms
```

До фактического запуска на VPS нельзя заявлять, что рабочие файлы побайтно совпадают.
Совпадение содержимого также не означает совпадение Git-истории.

## Что делать с рабочей копией VPS позже

Исходное состояние VPS: `main`, коммит `3597b85`, локальные правки двух файлов,
после чего последовательно применены три патча справки.
Расположение приложения: `/opt/interpain_b24forms`.
Сервис: `interpain-b24forms.service`, пользователь `www-data`, порт `3001`.
Docker на порту `3000` не затрагивается.

Не выполнять `git pull`, `git reset --hard`, `git clean`, массовый `git add .`
или переключение ветки поверх этих правок.
Не копировать подготовленный Nginx-шаблон поверх действующего TLS-конфига.

После проверки хешей и отдельного разрешения:

- Зафиксировать текущее состояние на новой резервной ветке, не коммитить в `main`.
- Предварительно проверить Git author/committer и добавить только явно перечисленные
  файлы приложения; `.env`, `.tmp.env` и другие секреты не добавлять.
- Получить актуальную ветку GitHub и сопоставить её с резервной веткой.
- При любых дополнительных изменениях остановиться для разбора различий.
- Отдельно согласовать приведение рабочей копии к выбранной ветке и любой перезапуск.

До выполнения этих шагов установленные файлы остаются локальными правками на VPS.
Обновление PR само по себе не меняет их и не делает рабочую копию сервера чистой.
