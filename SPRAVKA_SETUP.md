# Справка по мероприятиям

Новая страница: `/spravka/`. Серверный API: `GET /api/spravka`.
Существующая страница регистрации не меняется. Node.js 18+; дополнительные пакеты не нужны.

## Подключение

Используется существующий серверный `B24_WEBHOOK_URL`, а при его отсутствии — `BITRIX_WEBHOOK`.
Переменная `BITRIX24_WEBHOOK_URL` не нужна. Вебхук никогда не вводится на странице справки.

На сервере, в существующий `.env`, добавьте две настройки:

```dotenv
SPRAVKA_USERNAME=report
SPRAVKA_PASSWORD=ЗАМЕНИТЕ_НА_СЛУЧАЙНЫЙ_ПАРОЛЬ_ОТ_16_СИМВОЛОВ
```

Придумайте отдельный случайный пароль для справки; не используйте пароль от Битрикс24.
Не сохраняйте рабочий пароль в GitHub, исходниках HTML, заметках к pull request или чате.
Если вебхук уже работает для `/api/event/323`, повторно указывать его не нужно.
У пользователя вебхука должны быть права читать мероприятия и все нужные сделки.
Код использует только методы чтения CRM.

### Если используется Linux + systemd

В репозитории есть шаблон `deploy/interpain-b24forms.service`, читающий
`/opt/interpain_b24forms/.env`. Это пример конфигурации, а не подтверждение текущего
состояния вашего хостинга. Если установлен именно он:

1. Получите проверенную версию кода обычным для проекта способом.
2. Добавьте настройки в серверный `.env` через VS Code Remote SSH или SSH-редактор.
3. Ограничьте чтение `.env` владельцем сервиса/администратором, не делайте файл публичным.
4. Перезапустите установленный сервис: `sudo systemctl restart interpain-b24forms`.
5. Откройте `https://forms.eduinterpain.ru/spravka/` и введите логин и пароль справки.

Используйте только HTTPS: заголовок Basic Authentication не шифрует пароль самостоятельно.
Вход действует до выхода или перезагрузки вкладки: пароль не записывается в браузерные хранилища.
Защитите endpoint на уровне nginx/WAF от перебора пароля, особенно если он вынесен на Vercel.
В Express сохраняется существующее ограничение проекта в 60 запросов/минуту.

### Если используется Vercel

В проекте также есть `vercel.json`: маршруты новой страницы и API добавлены.
Добавьте `SPRAVKA_USERNAME` и `SPRAVKA_PASSWORD` в серверные Environment Variables
того же проекта и выполните новый deploy. Не добавляйте префикс `VITE_` или `NEXT_PUBLIC_`.
Для большого числа мероприятий/сделок убедитесь, что лимит времени функции допускает
полную загрузку: обработчик ограничивает проход примерно 55 секундами.
Обновление из GitHub может запустить автоматический deploy, поэтому публикацию кода
нужно согласовывать отдельно.

## Правила справки

- Только элементы смарт-процесса `1036` со стадией с точным названием «Реализация».
- Поле номера определяется по названию «Кодовое обозначение» в метаданных CRM.
- Заголовок: код | кликабельное название карточки | город без круглых скобок.
- Название карточки сохраняется, включая скобки внутри названия.
- Город по умолчанию извлекается из `ufCrm21EventAddr`, как в существующем API регистрации.
- Связь сделки: `UF_CRM_DEAL_1738519959225` содержит ID элемента мероприятия.
- Оплачено: «Оплачено, Собрать документы».
- Проверить ФЛ: «Проверить оплату ФЛ».
- Проверить ЮЛ: «Оформить договор/счет ЮЛ» + «Проверить оплату ЮЛ».
- Отказались: «Не приехали (проигранная)» + «Отмена с возвратом» + «Не успешно отучились».
- Если «(проигранная)» является только пометкой интерфейса, учитывается стадия «Не приехали».
- Считаются сделки, не сумма денег и не уникальные контакты.
- Одна и та же сделка повторно не учитывается. При множественной привязке она считается
  по одному разу в каждом указанном мероприятии.
- Сортировка: прямое строковое сравнение кодового обозначения по возрастанию,
  без сортировки по ID, дате или названию. При одинаковом коде сохраняется порядок выборки.
- Стадии ищутся во всех доступных воронках сделок; одинаковые названия включаются все.
- Неизвестное поле/отсутствующая необходимая стадия дают ошибку, а не ложные нули.
- Все страницы API загружаются; результат хранится в памяти сервера до 60 секунд.
- Кнопка «Обновить» запрашивает свежую выборку.
- Если обновление не удалось, предыдущие данные остаются с явным предупреждением.
- Это последовательное чтение API, а не транзакционный снимок: изменения CRM во время
  формирования могут повлиять на согласованность выборки.

## Необязательные настройки

```dotenv
EVENT_ENTITY_TYPE_ID=1036
SPRAVKA_CODE_FIELD=код_поля_camelCase
SPRAVKA_CITY_FIELD=код_отдельного_поля_города
SPRAVKA_VENUE_FIELD=ufCrm21EventAddr
SPRAVKA_DEAL_EVENT_FIELD=UF_CRM_DEAL_1738519959225
```

Не копируйте строки с условными кодами полей без необходимости.
`SPRAVKA_CITY_FIELD` имеет приоритет над извлечением города из места проведения.
Названия пользовательских полей берутся в формате camelCase из `crm.item.fields`.

Для неоднозначных названий стадий можно задать конкретные STATUS_ID через запятую:

- `SPRAVKA_STAGES_PAID`
- `SPRAVKA_STAGES_CHECK_INDIVIDUAL`
- `SPRAVKA_STAGES_CHECK_COMPANY`
- `SPRAVKA_STAGES_DECLINED`

Переменная заменяет весь набор стадий соответствующей группы, включая обе или все три
составляющие суммируемых строк. Не указывайте ID стадии в нескольких группах.

## Проверка после установки

1. Без пароля `/api/spravka` не возвращает данные.
2. После входа найдите мероприятие `26_11_07-08`, карточку ID 323.
3. Сверьте все четыре числа с ручными фильтрами CRM по связанным сделкам.
4. Проверьте, что `26_10_10-11` расположено перед `26_11_07-08`.
5. Нажмите название мероприятия, убедитесь, что открылась его карточка.
6. Нажмите «Обновить», затем «Выйти».
7. Проверьте, что регистрационная форма продолжает работать.

Автоматические тесты: `npm run test:unit`. Живой доступ к вашему вебхуку в среде
разработки не предоставлен, поэтому сверка реальных чисел обязательна после установки.

## Безопасность репозитория

В текущей исходной версии Git отслеживает файл `.tmp.env`, несмотря на запись
в `.gitignore`. Его содержимое при разработке справки не читалось.
Само имя не доказывает наличие секрета. Проверьте файл самостоятельно: если там
действующие доступы, отзовите их и удалите секреты из истории Git по согласованному плану.
Добавление в `.gitignore` не удаляет уже отслеживаемый файл.

В Express дополнительно закрыта публичная раздача исходников и конфигураций из
корня проекта. Публичная страница справки содержит только интерфейс входа;
данные доступны через защищённый API.
